# 호재·악재 페이지 (보류)

풍무역세권의 미래가치에 영향을 주는 사안을 모아 보여주는 두 번째 화면. 기획만 해 두고
구현은 보류한다.

## 왜

지금 앱은 "이 동 이 층에 해가 얼마나 드는가" 하나를 정확하게 답한다. 그런데 실제로 집을
고를 때는 그 옆에 "이 동네가 어디로 가는가"가 따라붙는다. 교통·개발·학교·규제가 값을
움직이는데, 그 정보는 블로그와 카페에 흩어져 있고 출처도 시점도 뒤섞여 있다.

## 구조

지도 화면과 나란한 탭 하나. 상단에 요약, 아래에 카드 리스트.

### 카드 한 장 = 사안 하나

```
[분류]  교통 · 개발 · 교육 · 환경 · 규제
[성격]  호재 / 악재 / 중립
[제목]  김포골드라인 증차
[진행]  ●━━●━━○━━○     계획 → 확정 → 착공 → 준공
[시점]  2027년 예정
[영향]  출퇴근 혼잡도 ↓ / 역세권 프리미엄 ↑      무엇에, 어느 방향으로
[근거]  김포시 보도자료 (링크)                    출처 없으면 카드가 될 수 없다
[사례]  별내선 개통 전후 별내지구 실거래 추이      조건이 닮은 사례의 결과
```

### 보기

- **필터** — 분류 / 성격 / 진행단계 / 시점(단기·중기·장기)
- **정렬** — 임박순(기본), 영향 크기순
- **타임라인** — 카드를 연도축에 늘어놓아 언제 무엇이 오는지 한 장으로
- **지도 연동** — 위치가 있는 사안(역·도로·학교·개발부지)은 지도에 핀을 찍고
  카드와 핀이 서로 하이라이트. 토지이용계획 레이어와 자연스럽게 붙는다

## 지킬 것

1. **모든 카드에 출처 링크 필수.** 없으면 등록하지 않는다. 이 저장소가 지금까지
   지켜 온 원칙이다 — 층수 하나도 동호수배치도나 카카오 라벨에서 읽어 근거를 남겼다.
2. **"미래가치 = 얼마" 같은 단정을 만들지 않는다.** 영향의 *방향*과 *근거*만 적고
   판단은 사용자 몫으로 남긴다. 일조량 화면의 붉은 경고문과 같은 톤이다.
3. **사례는 비교 가능한 것만.** 조건이 닮은 사례여야 한다. 아무 개발지나 끌어와
   "여기도 올랐다"고 붙이면 그 순간 이 앱은 홍보물이 된다.

## 데이터

`web/src/data/factors.json` 한 파일. 코드를 고치지 않고 카드만 추가·갱신한다.

```json
{
  "factors": [
    {
      "id": "goldline-cars",
      "category": "교통",
      "tone": "호재",
      "title": "김포골드라인 증차",
      "stage": "확정",
      "when": "2027",
      "effects": [
        { "what": "출퇴근 혼잡도", "dir": "down" },
        { "what": "역세권 프리미엄", "dir": "up" }
      ],
      "sources": [{ "title": "김포시 보도자료", "url": "..." }],
      "cases": [{ "title": "별내선 개통 전후 별내지구 실거래", "url": "..." }],
      "at": [126.7326, 37.6124]
    }
  ]
}
```

`tone` 은 호재/악재/중립, `stage` 는 계획/확정/착공/준공, `at` 은 있으면 지도에 핀.
