# 풍무역세권 일조 시뮬레이터 · 호반써밋 풍무 Ⅲ

지도 위에 **호반써밋 풍무 Ⅲ**(김포 풍무역세권 B-4BL)과 주변 단지의 건물을
실제 동 모양·실제 층수 그대로 3D로 세우고, 계절·시각별 그림자를 보여주는 웹앱.
지구 전체가 아직 나대지라, 빈 땅에 무엇이 들어서는지를 보여주는 **토지이용계획**
도 함께 얹는다.
지도는 브이월드 타일을 MapLibre GL 로 그리고, 건물은 그 위에 three.js 로 올린다 —
**돌리고 기울여서** 어느 방향에서든 볼 수 있다.

```bash
cp .env.example .env   # 브이월드 키를 채운다
cd web
npm install
npm run dev            # http://127.0.0.1:5173
```

브이월드 키는 **포트까지 포함한** 도메인이 등록돼 있어야 타일이 내려온다
(브이월드 > 마이페이지 > 인증키 관리). 등록되지 않은 주소로 열면 타일이 비고
지도가 회색으로 남는다.

## UI

모바일 우선 단일 레이아웃. 브레이크포인트도, 데스크톱 전용 화면도 없다 — 모든
치수가 `clamp()`로 뷰포트에 비례하므로 PC는 같은 화면이 늘어난 모습이다
(`web/src/styles.css`).

- **동 / 호수 선택**: 지도에서 건물을 탭하거나 드롭다운에서 동을 고르면 그 동이
  주황으로 강조되고, 층을 고르면 해당 층 밴드가 표시된다. 계단형 동에서는 그 층에
  실제로 도달하는 라인에만 밴드가 그려진다. **분석 대상인 3차 동만 고를 수 있다** —
  주변 단지는 그림자를 드리우는 역할만 한다.
- **동 숨기기**: 선택한 동의 `숨기기` 를 누르면 그 동만 그리지 않는다. **그림자는
  그대로 남는다** — 앞동에 가려 보이지 않던 뒷동 벽면과 바닥 그늘을 그 동이 실제로
  드리우는 그림자와 함께 볼 수 있다. 숨긴 동은 지도 좌상단 칩으로 되돌린다.
- **시각**: 6시 ~ 18시 슬라이더 (10분 단위)
- **계절**: 봄 3/20 · 여름 6/21 · 가을 9/22 · 겨울 12/21
- 지도는 **호반써밋 풍무 Ⅲ 필지에 맞춰**, 45° 기울어진 채로 열린다. 이후 이동·확대/
  축소·회전·기울이기는 자유다. 우하단에 `+` / `−` 와 **나침반**이 있고, 나침반을
  좌우로 끌면 방위가 돌고 위아래로 끌면 기울며, 누르면 정북·수평으로 돌아온다.
  필지를 기울여서도 담으려면 평면 기준보다 더 물러나야 하므로, 처음 줌은
  `fitBounds` 값에서 `BACKOFF` 만큼 빼서 연다 (`web/src/App.jsx`).

- **토지이용계획 겹쳐보기** (지도 좌상단 스위치, **기본 켜짐**): 용지별 색면과 이름표,
  지구 경계, 단지별 블록 코드(B1~B5·C5·D1~D4)를 얹는다. 이 지역에서는 "옆에 뭐가
  들어서나" 가 그림자만큼 궁금한 정보라 켠 채로 연다. 아래 "토지이용계획" 참고.
- **밤이 온다.** 해가 지평선 아래로 내려가는 앞뒤로 화면 전체가 서서히 어두워진다
  (고도 +6° ~ −8°). 3D 만 어둡게 하면 지도 바닥이 대낮으로 남아 어색해서, 지도까지
  덮는 한 겹으로 처리한다.
- **제목 아래에 붉은 경고문이 항상 떠 있다.** "참고용입니다. 모든 3D 건물은 층고와
  거리를 추정값으로 계산한 가상의 건물이므로 실제 일조량과 다를 수 있습니다." 화면이 그럴듯할수록
  이게 추정이라는 사실이 잊히므로 접히지도 닫히지도 않는 자리에 둔다. 첫 방문 안내에도
  같은 문구가 들어간다. 무엇을 반영하지 않는지는 아래 "한계" 에 있다.
- **첫 방문에는 조작법을 먼저 보여준다** (`web/src/Help.jsx`). 나침반 말고는 이 화면이
  3D 라는 표시가 없어서, 모르면 평면 지도인 줄 알고 나간다. 접속 기기에 맞는 쪽만
  띄우고(`(pointer: coarse)` 로 터치/마우스 판정), 한 번 닫으면 `localStorage` 에
  기억한다. 제목 옆 `?` 로 언제든 다시 연다.

**조작** (`web/src/lib/gestures.js`) — 화면에 있는 건 내려다보는 지도가 아니라 걸어서
돌아보는 모형이라, 터치 제스처를 MapLibre 기본값과 반대로 뒤집었다.

| | 터치 | 마우스 |
|---|---|---|
| 회전 · 기울이기 | 한 손가락 끌기 (좌우 = 회전, 상하 = 기울이기) | 우클릭 드래그 |
| 상하좌우 이동 | 두 손가락 끌기 | 좌클릭 드래그 |
| 확대 · 축소 | 두 손가락 벌리기/오므리기 | 휠, 더블탭, `+` / `−` |

핀치도 직접 처리한다. `jumpTo`·`panBy` 가 매번 `Camera.stop()` 을 부르는데, 그게
MapLibre 자체 핸들러를 리셋해서 두 손가락 이동이 일어날 때마다 진행 중이던
`touchZoomRotate` 제스처가 취소되기 때문이다.

**페이지 자체는 1배로 못 박는다.** 핀치는 지도를 확대하는 제스처지 브라우저를
확대하는 제스처가 아니다. 세 겹으로 막는다 — viewport 메타의 `user-scalable=no`
(안드로이드), 지도 위 `touchmove` 의 `preventDefault`(비-passive 리스너), 그리고
iOS Safari 가 앞의 둘을 모두 무시하고 보내는 `gesturestart`/`gesturechange` 차단.
`overscroll-behavior: none` 으로 당겨서 새로고침과 고무줄 반동도 없앴다.

모든 터치 대상은 44px 이상이고(`--ctl-h` 바닥값), 폼 컨트롤 글자는 16px 이상이다 —
iOS 는 그보다 작은 컨트롤을 누르면 페이지를 확대해 버린다. `viewport-fit=cover` 로
노치 아래까지 그리는 대신 `env(safe-area-inset-*)` 만큼 안쪽 여백을 준다.
- 3차 옥상에는 **주택형별 색과 라인**이 동·호 배치도와 같은 범례로 얹힌다
  (59A/59B/84A/84B/84C/84D). 색은 배치도 범례 스와치에서 직접 뽑았고, 칸 경계는
  분양 배치도에서 읽은 세대 라인 위치를 그대로 따른다.

분석 대상 넷이 35개 동 · 77개 볼륨, 여기에 그라센트 2개 단지와 업무시설 예상 매스가
더해져 화면에는 108개 볼륨이 선다.

**층수는 각 단지 동호수배치도의 라인(호 계열)별 최고층을 전량 판독한 값**이다.
한 동 안에서도 라인마다 최고층이 다르므로(예: 403동 = 17·17·23·27·29층),
같은 층수로 끝나는 라인들을 하나의 덩어리로 묶어 계단형 볼륨으로 세운다.
동 표기가 없는 필지는 근린생활시설로 보고 2층(9.3m)으로 통일했다.

높이 = 층수 × 2.9m. 건물은 최고층 슬래브에서 끝난다 — 최고층을 골랐을 때 그 위에
층으로 오해되는 덩어리가 남지 않게 **옥탑/파라펫을 세우지 않는다**
(`tools/build_data.py` 의 `ROOF_H = 0.0`). 실제 옥탑만큼 그림자가 짧게 나오는 건
아래 "한계" 에 적어 뒀다.

### 검증

카카오맵이 공사 중인 푸르지오 더 마크의 건축물 데이터를 표시해 주는데, 여기 값과
동호수배치도 판독값이 일치한다 — 예: 308·309동 `4-29F` + `6-28F`(본 데이터
`[29,29,29,29,28,28]`), 301동 `2-14F`(`[14,14]`), 311동 `2-15F`(`[15,15]`),
305동 `6-26F`(`[25,25,26,26,26,26]`).

### 3차 라인 위치 (`resolve_line_order`)

주택형별 하이라이트 시트 6장(84A/84B/84C/84D/59A/59B)에서 색칠된 덩어리 하나가
**세대 라인 하나**다. 8개 동 전부 덩어리 개수가 라인 수와 정확히 같아서(4·3·5·5·5·
4·4·4 = 34), 이 덩어리 중심점이 곧 라인 씨앗이 된다.

- 씨앗을 동의 장축 방향으로 정렬하면 동호수배치도 최하단 **타입 행과 글자 그대로
  일치**해야 한다. 8개 동 모두 한쪽 방향(01호 라인이 동쪽 끝)에서 정확히 일치한다.
  점수·허용오차 없이 문자열 비교로 끝나므로, 어느 셀이 어느 주택형인지와 라인
  배열 방향이 동시에 확정된다.
- 시트가 어느 주택형인지는 **동별 덩어리 개수**로 판정한다. 색칠된 동의 집합만
  보면 59A와 59B가 똑같이 405~408이라 구분되지 않지만, 405동은 59A가 2개 라인·
  59B가 1개 라인이라 개수는 갈린다.
- 정렬 축은 `principal_axis` 에서 `ux ≥ 0` 로 고정한다. 고유벡터 부호는 재현되지
  않아서 `refine_footprints.py` 가 카카오 푸트프린트를 반대로 자를 수 있다.

**계단형 볼륨도, 옥상의 주택형 셀도 이 씨앗에서 자란다** (`split_by_seeds`).
장축을 등분하는 직선 절단은 일자형 판상동에서만 맞고, 3차처럼 V자로 꺾인 동에서는
한쪽 날개를 통째로 한 칸으로 주고 반대쪽을 셋으로 쪼갠다. 씨앗에서 워터셰드로
키우면 경계가 실제 인접 세대의 중간에 생기므로 평면의 꺾임을 그대로 따라간다.

## 데이터 파이프라인 (`tools/`)

| 스크립트 | 역할 |
|---|---|
| `build_data.py` | 층수(LINES) + 1차 푸트프린트 → `web/src/data/buildings.json` |
| `trace_kakao.mjs` | 카카오맵 건축물 폴리곤 캡처 (`web/trace.html` 을 띄운다) |
| `refine_footprints.py` | 캡처한 폴리곤으로 푸트프린트 교체 |
| `make_ground.py` | 같은 캡처를 지면 텍스처로 → `web/public/ground*.webp` |
| `add_context.py` | 주변 단지(그라센트 1·2차) → `web/src/data/context.json` |
| `make_landuse.py` | 토지이용계획도 → `web/public/landuse.json` |
| `make_offices.py` | 업무시설 D1~D4 예상 매스 → `web/src/data/offices.json` |
| `fix_footprints.py` | 파이프라인 뒤 손보는 개별 교정 |
| `check_sun.mjs` | 태양위치·그림자 길이·데이터 정합성 + 3차 주택형 셀 검증 |
| `check_shadow.mjs` | 벽면·옥상 그림자 경계를 씬 레이캐스트로 이론값과 대조 |
| `check_resize.mjs` | 지도 크기가 바뀐 뒤에도 3D 가 같은 자리에 그려지는지 픽셀로 대조 |
| `smoke.mjs` | 실제 브라우저로 열어 볼륨 수·UI·렌더 시간 보고 + 스크린샷 |

```bash
npm install                      # tools/ 용 playwright
cd web && npm run dev &          # 개발 서버가 떠 있어야 한다
python tools/build_data.py
node   tools/trace_kakao.mjs
python tools/refine_footprints.py
NAME=kakao_trace SCALE=1 OUT=ground       python tools/make_ground.py
CENTRE=37.6145,126.7334 LEVEL=2 W=5500 H=3700 NAME=kakao_wide node tools/trace_kakao.mjs
NAME=kakao_wide  SCALE=0.5 OUT=ground_wide python tools/make_ground.py
python tools/add_context.py
python tools/make_landuse.py
python tools/make_offices.py      # landuse.json 을 읽으므로 순서를 지킨다
node tools/check_sun.mjs && node tools/check_shadow.mjs
node tools/check_resize.mjs && node tools/smoke.mjs
```

앱은 카카오맵을 쓰지 않지만 푸트프린트의 출처는 여전히 카카오다. 그래서 트레이싱만
`web/trace.html` — 카카오 SDK 하나만 띄우는 페이지 — 로 분리해 뒀다. 같은 vite 개발
서버가 서빙하므로 `%VITE_KAKAO_JS_KEY%` 치환도 그대로 된다. 카카오 JS 키에 등록된
도메인이 `http://localhost:5173` 이라 이 페이지만 `localhost` 로 연다.

`asset/` 은 분양 홍보물 원본(배치도·주택형 시트·호갱노노 캡처)이다. 파이프라인을
다시 돌릴 때만 필요하고, 앱은 결과물인 `web/src/data/buildings.json` 만으로 돈다.

### 주변 단지 (배경 매스)

| 단지 | 타워 | 층수 | 근거 |
|---|---|---|---|
| 풍무역세권 수자인 그라센트 1차 | 12 | 29 | 카카오 라벨 15~29F, 10개동 1,071세대 |
| 풍무역세권 수자인 그라센트 2차 | 8 | 28 | 카카오 라벨 13~27F, 7개동 639세대 |

그림자 계산에는 들어가지만 분석 대상은 아니다 — 동·호수로 고를 수 없다
(`DONG_INDEX` 가 3차만 담는다). 동호수배치도가 없어 **동별 층수는 단지 홍보물의
동호수배치도 이미지에서 읽어** 동마다 따로 넣었고, 나머지는 주 단지와 똑같이 그린다.

- 카카오는 아파트 필지를 고유한 베이지로 칠한다. **준공은 `#f4ede1`, 공사 중은
  `#f0e8d8`** 로 다르다 — 예정 단지는 이걸 모르면 시드가 필지를 못 잡는다
- **필지 안의 흰 덩어리가 전부 건물은 아니다.** 단지 내 도로·광장·보행로도 같은
  흰색이다. 주축 bounding box 를 얼마나 채우는지(fill)로 가른다. 단지 내
  근린생활시설·상가·어린이집은 **1층**으로 낮게 세운다
- 카카오가 한 덩어리로 그려 버린 동은 침식으로 갈라 낸다. 그래도 안 갈리는
  수자인2차 107동은 **106동 푸트프린트를 복사해** ±8 m 격자탐색으로 자리를 맞췄다

**오퍼스 한강 스위첸, 한강 푸르지오 리버프론트는 넣지 못했다.** 고촌읍 향산리 부지인데
카카오가 아직 옛 마을·농장 건물만 그린다. 그려지면 `add_context.py` 의 `COMPLEXES` 에
시드와 층수 한 줄만 더한다 (오퍼스 지상 25층 9개동 1,029세대, 리버프론트 지상 38층
12개동 2,432가구).

**풍무역 일대 상가도 없다.** 카카오는 일반 시가지에 개별 건물 폴리곤을 그리지 않고
블록 채움만 준다. 건물을 가르는 건 회색 윤곽선뿐인데 POI 아이콘·라벨이 그 선을 끊어서
level 1·2 어느 쪽에서도 30% 남짓만 닫힌 도형으로 잡힌다.

### 지면 텍스처

브이월드 기본지도는 이 신축 단지를 아직 그리지 않는다 — 필지 경계만 있고 동이 없으며,
항공영상은 **개발 이전의 밭·비닐하우스**다. OSM 도 이 일대는 거의 백지다. 4개 단지를
실제로 그리는 건 카카오뿐이라, 푸트프린트를 뽑으려고 어차피 찍는 그 캡처를 그대로
지면에 깐다 (`make_ground.py` → MapLibre `image` 소스). 바깥은 계속 브이월드가
채우고, 경계는 70 m 알파 램프로 녹인다.

- 캡처 affine 이 회전 없는 메르카토르 정렬이라, 이미지 네 모서리 좌표가 역변환 한
  번으로 정확히 떨어진다 (`web/src/data/ground.json`)
- **두 겹이다.** 넓은 쪽 `ground_wide.webp` (1 px/m, 2750 x 1850 m, 0.39 MB) 이 주변
  단지가 선 자리를 덮고, 그 위에 부지만 `ground.webp` (4 px/m, 780 x 1080 m, 0.44 MB) 로
  한 번 더 깐다. 정작 들여다보는 곳만 선명하면 된다
- 4 px/m 는 줌 18 에서 화면과 1:1 이다. 그 위로 확대하면 흐려진다
- **`ground*.webp` 는 커밋하지 않는다** — 카카오맵 렌더를 그대로 담은 이미지다.
  없으면 앱은 브이월드만 깔고 그대로 돈다 (`ground` 소스 오류는 무시한다)

> 카카오 운영정책은 *"실시간 호출 방식과 오프라인 사용 시 CI, 출처를 정확하게 기입한
> 경우에만 일부 캡처를 허용"* 한다고 밝히고 있다. 공개 배포한다면 카카오 CI 와 출처
> 표기를 넣고, 그 전에 카카오 데브톡에 문의해라.

**푸트프린트는 카카오맵 자체 건축물 폴리곤을 트레이싱한 값**이다. 4개 단지 전부
카카오에 실제 폴리곤이 있어서, 그걸 **줌1(4 px/m)** 로 렌더해 건축물 채움색만
추출하고 역투영해 WGS84로 되돌린다. 그래서 3D 건물이 지도의 흰 건물 모양에서
그대로 올라온다.

- **ROI는 카카오가 칠한 필지(대지) 색을 플러드필한 영역**이다. 도로도 같은 흰색
  계열로 그려지므로, 필지 폴리곤을 넓혀서 ROI로 쓰면 도로가 통째로 "건물"이 된다.
- 건축물 채움은 `#fdfdfb`, 바탕 흰색은 `#ffffff` 로 미세하게 다르다. "거의 흰색"으로
  잡으면 필지 안의 미개발 백지까지 건물이 되므로 정확한 색으로 판정한다.
- 동 번호·면적 라벨은 채움에서 파여 있다. 그대로 두면 라벨이 걸친 동이 조각나므로,
  **라벨 주변에서만** 닫힘(closing)을 적용해 홈을 메운다.
- 한 동은 세대 단위 블록들의 나열로 그려진다. 기존 위치와 겹치는 블록을 씨앗으로
  잡고, 거기에 **5 m 이상 면을 맞대고 붙은** 블록을 흡수해 동을 완성한다. 모서리만
  스치거나 이미 확보한 면적보다 큰 덩어리는 다른 건물로 본다.
- 마지막으로 동마다 **자기 직교 프레임에서 1 m 격자로 정규화**한다. 벽면 방향은
  외곽선 변의 길이가중 원형평균(90° 모듈로)으로 잡는다 — 최소면적 사각형은 날개형
  동에서 몇 도씩 틀어져 40 m 벽에 톱니를 남긴다.
- 도로 조각은 폭 6 m 미만이거나 길이/폭 8 초과면 버린다.
- 카카오맵이 라벨을 가려 잡히지 않는 동(더마크 301·302)은 트레이스에서 직접 읽은
  라벨 좌표를 `DONG_ANCHOR` 에 둔다.
- 카카오가 건축물 폴리곤으로 그리지만 배치도상 건물이 아닌 조각(408동 북동쪽
  정사각형, 405동 서쪽 ㄴ자)은 `NOT_BUILDING` 에 좌표로 적어 제외한다. 라벨도
  세대 구획선도 없어 래스터만으로는 동의 날개와 구분되지 않는다.
  `DIAG=1 python tools/refine_footprints.py` 로 모든 조각의 중심 좌표를 찍는다.

## 토지이용계획

`tools/make_landuse.py` 가 `asset/ground/계획도1.jpg`(S=1/3,000 정북 도면)를 색으로
갈라 폴리곤으로 뜬다. 도면을 이미지로 얹지 않는 이유는, 얹으면 카카오 지면과 색이
겹쳐 지저분해지고 확대하면 흐려지기 때문이다.

- **정합**은 블록 기호 B1~B5·C5 여섯 점(우리가 이미 좌표를 아는 단지)으로 맞춘
  상사변환이다 — 축척 0.529 m/px, 회전 −0.2°. 기준점이 '블록 기호 위치 vs 건물
  무게중심' 이라 평행이동이 남는데, 도면 필지 마스크와 카카오 필지 마스크의 겹침이
  최대가 되는 값(**동 16 m, 북 3 m**)을 재서 보정한다 (`tools/_fit2.py`). 보정 뒤
  단지별 겹침은 0.82~0.92 다
- **색은 범례가 아니라 도면 본문에서 잰다** (`tools/_body.py`). 범례 스와치가 본문보다
  어둡게 찍혀 있어 — 공원 범례 `(1,127,1)` vs 본문 `(4,182,4)`, 광장 `(0,127,126)` vs
  `(5,186,186)` — 스와치 색으로 따면 공원·광장·공공공지가 통째로 안 잡힌다
- **윤곽은 직선을 맞춰 갈아 낀다** (`regularize`). 색면 위에 글자·필지선·JPEG 얼룩이
  겹쳐 있어 색으로만 따면 테두리가 톱니처럼 찢긴다. 윤곽을 '한 직선으로 볼 수 있는
  구간' 으로 잘라 총최소제곱으로 직선을 세우고, 이웃한 직선의 교점을 꼭짓점으로 쓴다.
  그 폴리곤의 주방향(길이 가중 평균)과 15° 안으로 나란하거나 직각인 변은 아예 그
  각도로 못 박아 사각형이 진짜 직각 사각형이 되게 한다
- 직선화가 실패하면 **`None` 을 돌려준다.** 원본 윤곽을 그대로 돌려주면 부르는 쪽의
  면적 검사가 당연히 통과해 촘촘한 톱니 점이 그대로 나간다 (한때 파일이 19 KB 에서
  303 KB 로 부풀었다)
- 색만으로 안 갈리는 것은 손으로 잡는다 — 중학교/초등학교는 붙어 있어 위도로 쪼개고
  (`SPLIT`), 도면에 기호로만 적힌 것은 좌표로 고쳐 부르고(`RENAME`), 폐기된 계획은
  뺀다(`DROP`). 도면 자리와 실제로 들어선 자리가 다르면 획지 모양만 옮긴다
  (`RELOCATE` — 사우동성당이 사우동 496-1 로 바뀐 경우)

### 업무시설 D1~D4 (예상 매스)

아직 아무것도 안 지어진 땅이라 트레이싱할 형상이 없다. `tools/make_offices.py` 가
필지와 계획 층수, 용적률 500% 로 매스를 역산한다.

| 획지 | 부지 | 층수 | 동 | 건축면적 | 건폐율 | 높이 |
|---|---|---|---|---|---|---|
| D1 | 8,456 m² | 10 | 3 | 4,228 m² | 50% | 36.0 m |
| D2 | 5,060 m² | 10 | 2 | 2,530 m² | 50% | 36.0 m |
| D3 | 3,433 m² | 14 | 2 | 1,226 m² | 36% | 50.4 m |
| D4 | 1,457 m² | 14 | 1 | 520 m² | 36% | 50.4 m |

- 연면적 = 부지면적 × 용적률, 층수로 나눈 값이 건축면적이다. 층고는 4.0 m 가 아니라
  **3.6 m** — 업무·근린생활은 아파트(2.9 m)보다 높지만 대형 오피스만큼은 아니다
- 배치는 필지의 최소면적 외접 사각형을 같은 비율로 줄여 가운데 놓고, 긴 변을 따라
  8 m 씩 띄워 여러 동으로 나눈다. 통짜 매스 하나면 창고처럼 보인다
- **획지 번호는 도면 어디에도 글자로 없다.** 이 지구의 블록 번호가 북서 → 남동 순
  (B1 그라센트2차가 북서, B5 호반1차가 남동)이라 업무시설도 같은 순서로 매겼다
- D4 는 필지가 짧고 뭉툭해 최소외접 사각형의 긴 변이 90° 돌아 잡힌다. 같은 가로변에
  나란히 선 D3 의 방향을 빌려 쓴다
- 실측이 아니라 계획을 읽은 추정이므로 `kind: planned` 로 내고, 렌더러가 **청록
  반투명**으로 그려 실측 동과 구분한다. 이름표도 같은 색이다

## 렌더링

`web/src/lib/buildings3d.js` — MapLibre 의 GL 컨텍스트를 공유하는 커스텀 레이어
(`renderingMode: '3d'`)다. 씬은 데이터 원점을 중심으로 한 **로컬 ENU 미터 좌표**
(x 동, y 북, z 상)에 있고, 모델 행렬 하나가 그걸 지도의 메르카토르로 얹는다.
미터→메르카토르 환산은 `MercatorCoordinate.meterInMercatorCoordinateUnits()` 가
그대로 주므로 투영을 가정하는 코드가 없다. 태양 위치는 NOAA 알고리즘(`sun.js`), KST 기준.

- **깊이는 Z버퍼가 정한다.** 화가 알고리즘도, 저층동을 먼저 깔던 예외도 없다.
  기울이든 돌리든 앞뒤가 스스로 맞는다.
- **그림자는 방향광의 깊이 맵**이다. 땅·이웃 동 옥상·이웃 동 벽면이 전부 같은 한 번의
  패스에서 나오고, 건물이 **자기 자신에게도** 그림자를 드리운다. 지면은 `ShadowMaterial`
  평면 하나라 지도 타일이 그대로 비쳐 보이고 그늘만 얹힌다.
- 깊이 맵은 **해·숨김·선택이 바뀔 때만** 다시 굽는다(`shadowMap.autoUpdate = false`).
  이동·확대·회전·기울이기에는 다시 굽지 않으므로 조작 중에도 프레임이 싸다.
- 그림자 절두체는 태양 고도로 구한 도달거리(`reach = h / tan(고도)`, 14h 상한)만큼
  부지 박스를 넓혀 광원 좌표계에서 딱 맞춘다. **지면 평면도 같은 크기로 맞춘다** —
  절두체 밖의 수광면은 깊이 맵의 가장자리를 물어와 통째로 검게 나온다.
- 향에 따른 명암과 그림자 깊이는 **같은 하나의 빛**이 낸다. three 의 Lambert 출력이
  `albedo × (ambient + sun × NdotL) / π` 라 둘의 합을 π 로 두면 정면으로 받는 면이
  재질 색 그대로 나오고, ambient 만 남은 면은 그 0.72 배가 된다 — 예전 렌더러의
  `CAST` alpha 0.30 과 같은 깊이다.
- **층 구분선은 지오메트리가 아니라 텍스처**다. `ExtrudeGeometry` 의 측면 UV 가 월드
  단위라 v 가 층 간격(2.9 m)에 정확히 물리고, 층이 텍셀보다 얇아지면 밉맵이 알아서
  선을 지운다 — 예전에 "2.6 px 미만이면 생략" 으로 손수 하던 일이다.
- **동마다 실루엣 외곽선**을 두른다. 이웃한 동은 색이 같아서 선이 없으면 407동과
  408동이 한 덩어리로 붙어 보인다. `EdgesGeometry` 를 9° 임계로 뽑아 트레이싱
  외곽선의 1° 계단이 세로선 다발이 되지 않게 하고, 면은 `polygonOffset` 으로 살짝
  물려 선이 면과 다투다 점선처럼 끊기지 않게 한다.
- **three 에게 드로잉 버퍼 크기를 매 프레임 다시 알려 준다.** three 는 렌더러를 만든
  시점의 캔버스 크기를 붙들고 있는데, 그림자 맵을 다시 굽는 프레임은 렌더타깃을
  되돌리면서 그 크기로 뷰포트를 복원해 버린다. 지도 높이가 한 번이라도 바뀌면
  (공지 닫기, 메뉴 접기, 창 크기, 기기 회전) 그 프레임만 3D 가 어긋난 크기로 그려지고,
  시각 슬라이더는 매 스텝 다시 구우므로 끄는 내내 화면이 깜빡인다. `setSize` 는 쓰면
  안 된다 - 캔버스 크기와 style 을 직접 건드려 MapLibre 의 리사이즈와 서로 밀어낸다.
  `check_resize.mjs` 가 이걸 픽셀로 잡는다
- **숨긴 동은 아무것도 그리지 않지만 그림자는 계속 던진다.** `visible = false` 는
  그림자 패스에서도 빠지므로, 대신 `colorWrite`·`depthWrite` 를 끈 재질로 바꾼다.
- 건물 선택은 `Raycaster` 다 — 기울인 상태에서도 화면에 보이는 그대로 집힌다.
- **해 뜨고 지는 앞뒤 30분(고도 4.5° 미만)은 그림자를 그리지 않는다.** 그 각도에서
  계산대로면 110 m 짜리가 1.3 km 를 드리우는데, 실제로는 사이의 건물·지형이 끊고
  직사광도 산란광에 묻혀 그런 그늘이 지지 않는다. 건축법이 보는 동지 09~15시는
  고도 11.4° 이상이라 판단 구간은 그대로 남는다. 4.5~6.5° 에서 짧게 페이드한다
- 남아 있는 그림자도 **멀어질수록 옅어진다**(대기 산란). 감쇠 구간은 그림자 길이에
  맞춰 늘어난다
- `check_shadow.mjs` 가 합성 박스 두 개를 실제 씬에 넣고, 렌더러가 쓰는 바로 그
  광원 방향으로 레이를 쏴 벽면 그림자 상단이 `h − L·tan(고도)`, 옥상 그림자 끝이
  `(h−h')/tan(고도) − L` 인지 확인한다 (7개 케이스, 오차 0.2 m 이내).

## 한계

- 발코니 돌출·창호 위치·수목·지형 고저 미반영 (외벽면 기준)
- **옥탑/파라펫(실측 기준 약 3.5m)을 세우지 않는다.** 그만큼 그림자가 짧게 나오므로
  결과는 실제보다 낙관적이다 — 겨울 오후 4시(고도 11.7°)면 약 17m 차이다.
  다시 세우려면 `tools/build_data.py` 의 `ROOF_H` 를 3.5 로 되돌리고 파이프라인을
  다시 돌린다
- 푸트프린트는 카카오맵 렌더 타일에서 추출한 파생 데이터다. 벡터 원본이 아니므로
  ±0.5 m 수준의 래스터화 오차가 남고, 카카오 데이터가 갱신되면 다시 트레이싱해야 한다
- 동 라벨이 없는 필지는 사용자 기준대로 근린생활시설 2층으로 세운다. 카카오가
  건축물로 그리는 지하주차장 램프 상부 등도 여기에 섞일 수 있다
- 1차·2차·더마크의 라인 배열 방향은 3차처럼 확정할 자료가 없어 정방향 가정
  (라인별 최고층 값과 최고 높이는 판독값 그대로)
- 직사광 기준. 대기 산란광은 밝기로 계산하지 않고, 먼 그림자를 옅게 하는 데만 쓴다
- **업무시설 D1~D4 는 실측이 아니라 계획에서 역산한 예상 매스다.** 실제 배치·형상은
  건축 인허가에서 달라진다. 그림자 계산에는 그대로 들어간다
- 토지이용계획 폴리곤은 스캔 도면에서 색으로 딴 파생 데이터다. 정합 잔차가 자리마다
  10~20 m 남고, 필지 경계는 실제 지적선이 아니라 도면 색면의 외곽선이다
- 지면 텍스처는 캡처 시점에 고정된 정지 이미지다. 카카오 데이터가 갱신되면
  `trace_kakao.mjs` → `make_ground.py` 를 다시 돌려야 한다. 줌 18 을 넘기면 흐려진다

## API 키

키는 **저장소 루트 `.env` 한 곳**에만 둔다. 코드에는 없고, `.env` 는 커밋하지
않는다. 처음 받았다면:

```bash
cp .env.example .env     # 값을 채운다
```

| 이름 | 쓰는 곳 | 비고 |
|---|---|---|
| `VITE_VWORLD_KEY` | `web/src/App.jsx` — 지도 타일(WMTS) | 브라우저에 노출된다. 브이월드에 **포트까지 포함한** 도메인을 등록해야 동작한다 |
| `VITE_KAKAO_JS_KEY` | `web/trace.html` — 건축물 폴리곤 트레이싱 전용 | 앱은 쓰지 않는다. Kakao Developers > 플랫폼 > Web 에 `http://localhost:5173` 등록 |

`web/vite.config.js` 의 `envDir` 이 루트를 가리키므로 `web/` 과 `tools/` 가 같은
파일을 읽는다. 실제 환경변수가 있으면 그쪽이 우선이라 CI 에서는 `.env` 없이 주입해도
된다.

`VITE_VWORLD_KEY` 가 없으면 앱이 "지도를 불러오지 못했습니다" 를 띄운다.

지도 우하단의 **브이월드 출처 표시는 이용약관상 필수**다. 눈에 덜 걸리게 각주
크기로 낮춰 뒀을 뿐(`styles.css`), 지우면 안 된다.
